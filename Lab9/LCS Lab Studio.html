Self-learning: from O(m×n) memory to linear space.

Four questions from the lab sheet, each with something you can run: the two-row version, why it loses the answer, Hirschberg's repair, how LCS differs from its cousins, and where it is used.

Q1

Two-row LCS

Cell L[i][j] only reads row i−1 and row i. Keep two rows, swap them after each pass, and make the shorter sequence the columns. Time stays O(m·n); space drops to O(min(m,n)).

Memory for long documents

Counting 8 bytes per cell. Dropping from a full table to two rows is the difference between hundreds of megabytes and a few kilobytes.

See it run

Open the visualizer in two-row mode. Old rows fade as soon as they are no longer needed, so you can see the length survive and the path disappear.

Verified in the code: two-row length equals the full-table length and a brute-force recursion on 300 random inputs and on a 2000 × 1500 pair.

Q3

Why two rows lose the answer: Hirschberg's fix

Traceback needs the cells it walks through, and the two-row method has overwritten them. Hirschberg's algorithm splits X in the middle, scores both halves against Y with two rows (one forward, one backward), picks the column where the scores add up highest, and recurses on the two sub-problems.

Brute-force recursion vs dynamic programming

Worst case for the plain recursion: two strings of length n with no matching characters. It re-solves the same sub-problems over and over. The DP table solves each of the n² sub-problems once.
